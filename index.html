🔎 符號怎麼看

  • [0]、[1]、[2]：List 的第幾格。程式是從 0 開始數，所以 [0] 是第 1 格、[1] 是第 2 格。
  • 「A001」：格子或信箱裡裝的值，「」裡面就是實際的文字。
  • [ …, … ]：把一整個 List 的內容寫在同一行，例如 [ 第 1 期起, 第 13 期起 ] 代表這個 List 有 2 格。
  • { 鑰匙: 值, … }：把一整個 Map 寫在同一行，冒號左邊是鑰匙、右邊是內容。
  • ( A001, B, 1, 1 )：一把 FormKey，括號裡依序是 ApplyId、Type、ApplyForm、MainCreditKind 這 4 個欄位的值。

架構圖

🎯 這張圖的目的：看這支 API 跟哪些角色合作：誰接請求、誰處理、誰查資料庫、誰包裝回應。

📖 白話：Controller 是櫃台，SvcImpl 是承辦員。承辦員自己不碰資料庫，而是把 SQL 檔名交給 SqlUtils（去檔案櫃拿 SQL 範本），再交給 SqlAction（真的跑去資料庫查）。

🧰 工具在做什麼

工具 比喻 在這支 API 做什麼
SqlUtils 檔案櫃 用檔名取出 resources/sql/ 裡的 SQL 範本
SqlAction 跑腿 拿 SQL 和參數 paramMap 真的去資料庫查。queryForList 回 List<Map>（query_001），queryForListVO 直接回物件（query_002、003）
ObjectMapper 轉換器 把查到的利率 FormValueVO 轉成下行要的 ApplyRate 物件，只留 10 個欄位
NormalResponseFactory 包裝員 把整理好的結果包成統一的回應格式 ResponseTemplate，每支 API 回給前端的外框都長一樣

  • [0]、[1]、[2]：List 的第幾格。程式是從 0 開始數，所以 [0] 是第 1 格、[1] 是第 2 格。
  • 「A001」：格子或信箱裡裝的值，「」裡面就是實際的文字。
  • [ …, … ]：把一整個 List 的內容寫在同一行，例如 [ 第 1 期起, 第 13 期起 ] 代表這個 List 有 2 格。
  • { 鑰匙: 值, … }：把一整個 Map 寫在同一行，冒號左邊是鑰匙、右邊是內容。

  • DetailList 每一列是 Map<String, String>，所以鑰匙是程式裡寫死的大寫名稱（例如 APPLY_FORM_NM），值全都是字串。

  • Map 的鑰匙順序不固定（HashMap），實際回傳的順序可能和這裡不一樣，不影響使用。

📖 白話：@Async 就像主管同時派 3 個同事各自去查資料，大家一起跑、不用排隊；CompletableFuture 是「取貨單」，allOf(...).join() 是「等 3 張取貨單都能領了再繼續」。

🧰 工具在做什麼

工具 比喻 在這支 API 做什麼
CQYAPRLTQAsyncService 同時派出去的小幫手 用 @Async 同時呼叫 3 支 API 的 Svc。回來的是 CompletableFuture（取貨單），allOf().join() 等 3 張都能領才繼續；任一個出錯，整支失敗
JPA Repository 自動產生 SQL 的查詢員 照方法名稱產生 SQL，例：findByApplyIdAndTypeAndItemKdIn = WHERE APPLY_ID = ? AND TYPE = ? AND ITEM_KD IN (…)；findById = 用主鍵查一筆
CommCodeUtil 代碼字典（共用函式庫） 翻幣別、判斷是不是理財型科目、IS_LAW_121 名稱
TranslateUtil 數字轉國字 承作方式序號 1 →（一）
NormalResponseFactory 包裝員 把整理好的結果包成統一的回應格式 ResponseTemplate，每支 API 回給前端的外框都長一樣
